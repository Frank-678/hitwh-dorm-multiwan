# 手动刷新时自动认证：集成设计

本文件记录已落地的集成设计，包括凭据弹窗、手动刷新认证和随机添加 WAN。代码及隔离测试已实现；真实校园网对新随机 MAC 的接入许可仍需现场验证。

## 路由器图形界面与离线包

当前主入口是 OpenWrt 24.10 的 LuCI“多路合并管理器”。IPK 同时提供 CLI、rpcd/ucode 接口、专用 ACL 与共享页面，路由器不安装 Python；旧电脑端 Python 服务保留为可选调试入口。

新安装将物理 WAN 作为底层接口，`main_enrolled=0`，初始线路池为空。新增均创建独立虚拟线路；升级保留旧配置。逐条刷新调用 `hitwh-mwan refresh <WAN>`，只认证指定的离线节点；全体按钮调用不带参数的刷新。

GUI 通过 LuCI 登录会话和同源 MessageChannel 桥接调用 rpcd，只有管理写权限能够读取凭据或开始操作。读取凭据是显式、短时请求；新增、刷新、删除和修改通过受限异步任务执行。JSON 交接文件位于 root `0700` 的 `/tmp` 子目录，文件 `0600`，读取后立即 unlink，凭据不进入参数或环境变量。任务无自动重试，已经提交的单次操作在关闭页面后仍可能完成，最长约 300 秒。

包升级、重装、卸载保留网络身份和凭据；删除节点必须由 GUI/CLI 明确执行。IPK 只包含必要脚本/静态资源，文件内容上限 512 KiB，安装前要求至少 4 MiB 剩余空间，包含 opkg 元数据余量。网络快照保留 8 份、包安装快照保留 3 份，图表历史只在浏览器内存中保留。

## 目标与触发边界

只有用户执行 `hitwh-mwan refresh`、点击 dashboard 的“刷新线路”按钮，或显式执行 `hitwh-mwan add random` 时，才允许尝试校园网认证。`add random` 只认证本次新建的一条线路。掉线本身只触发既有的健康检查和出口切换，不触发登录。

| 入口 | 允许提交认证 |
| --- | --- |
| `hitwh-mwan refresh` | 是，仅处理仍离线且配置了对应凭据的受管 WAN |
| dashboard 的“刷新线路”按钮 | 是，继续调用同一个 `hitwh-mwan refresh` |
| `hitwh-mwan add random` | 是，仅对本次新建的 WAN 进行一次初始认证 |
| 周期监控、启动、接口 hotplug、`hitwh-mwan-update` | 否，不读取认证凭据 |
| `list`、`add <MAC>`、`edit`、`set-main` | 否，即使其健康检查发现线路离线 |
| dashboard 页面打开、浏览器 F5、自动采样与轮询 | 否 |

LuCI 的任务执行器与电脑端调试服务均调用统一 CLI，不在浏览器实现锐捷认证协议。

## 集成方式

复用 Auto-Ruijie-Tool 使用的 ePortal 登录协议，新增小型一次性认证辅助程序；不直接运行其完整 Go 主流程。原项目包含桌面通知、静态登录参数和登录前自动踢设备的逻辑，均不适合直接接入本项目。

认证辅助程序由 `cmd_refresh` 和 `add random` 的初始认证流程调用。后台更新器保持只负责健康判断、策略路由和在线出口集合。

手动刷新流程：

1. 获取 `flock` 管理锁，与 add/remove/edit/凭据写入协调，防止 CLI 和 dashboard 同时执行恢复。锁随进程退出释放。既有 updater 锁仍只保护路由更新，不能在整个认证期间持有它。
2. 执行既有健康检查，记录本轮开始时的离线受管 WAN。全部在线时直接返回，不读取密码或提交登录。
3. 仅缺少 DHCP 地址时重连接口并等待地址；已有地址的离线接口不重启。再运行更新器，为新地址准备源地址策略路由。
4. 只对本轮仍离线、有 DHCP 地址、且存在对应凭据配置的 WAN 尝试认证。未配置凭据的线路继续保留原有恢复行为。
5. 绑定该 WAN 的当前 IPv4 地址获取最新门户跳转，核对门户与预先配置的可信地址一致；确认确实是认证拦截，而不是仅凭超时就发送密码。
6. 查询门户页面配置和服务信息，按实际要求构造登录表单。当前已验证的门户无需验证码、无需密码加密、无需 service 选择；不能将这些条件假定为永久不变。
7. 本轮每条线路最多提交一次登录；错误密码、验证码要求、未支持的加密方式或服务选择应返回明确的固定错误类别，等待下一次人工刷新。
8. 登录结果为 success 后，仍须绑定原 WAN 验证健康地址返回期望的 204。接口地址在过程内发生变化时放弃这次认证，不能把旧参数应用于新地址。
9. 执行最终更新，把恢复的线路加入分流池并完成主出口切回。沿用 `RESULT attempted recovered remaining` 汇总协议。

没有定时认证任务、后台重试队列或掉线后延迟登录。单次手动刷新中的请求有有限超时；退出后不继续认证。

## 随机添加 WAN

命令：

```sh
# 用户名和密码由交互读取，不接收密码参数
hitwh-mwan add random
```

该命令生成的是本地管理的**单播** MAC，不是多播 MAC。最简单的生成方式是固定首字节为 `02`，从 `/dev/urandom` 取其余五字节；这提供 40 个随机位。`02` 的单播位为 0、本地管理位为 1，与现有 `valid_mac` 拒绝多播地址的逻辑一致。语义依据：[RFC 9542，第 2.1.1 节](https://www.rfc-editor.org/rfc/rfc9542.html#section-2.1.1)。

只有随机生成本身不能保证唯一。候选地址需要同时避开：

- UCI network 中所有接口和设备配置的 MAC，包括主 WAN、保留接口和非受管接口；不能只复用当前 find_by_mac 检查 wan2–wanN。
- 所有运行时网络设备的 MAC，包括主物理 WAN 和 LAN/Wi-Fi 设备。
- 已保存的认证配置关联 MAC。
- 路由器上的独立 MAC 历史，例如 `/etc/hitwh-mwan/mac-history`。已经删除的线路和已经尝试使用的地址仍保留记录，以满足“与已记录地址不同”的要求。

历史文件只记录 MAC 和必要状态，不记录账号或密码。初次接入历史记录时可从已有网络配置备份中导入已记录 MAC，读取时仅提取 MAC 字段。它不能证明局域网其他未记录设备没有同一地址；本功能保证的是本机已记录集合内不重复。

添加流程：

1. 检查是否存在可用受管编号，继续跳过 wan6。容量已满或环境不支持时，在录入密码及网络修改前失败。
2. 要求用户为本次添加交互输入非空 username/password，密码不回显。取消或输入无效时不创建 WAN；不自动复用聊天中的凭据或其他 WAN 的账号。
3. 获取与 add/remove/edit/refresh 协调的管理锁，重新确认空闲编号，生成并检查候选 MAC。去重后先登记历史，再创建接口，防止并发添加选到同一地址。生成重试有上限；随机源失败时直接报错，不以时间戳或 PID 代替。
4. 将该 MAC 固定写入新接口配置，并将用户凭据写入新 WAN 对应的 root-only 私有配置；凭据关联接口名和生成的 MAC。网络配置不含密码。创建或写入失败时撤销本次尚未完成的新配置与临时秘密文件，不影响既有线路；已登记 MAC 保留历史。
5. 申请 DHCP，验证实际设备 MAC 与生成值一致，通过更新器建立对应源地址路由。没有 DHCP 时不提交登录。
6. 绑定新 WAN 的当前 IP 获取门户参数，并调用与 refresh 共用的一次性认证程序。只为新接口提交一次，不认证或注销已有接口，也不调用踢设备逻辑。
7. 通过 204 检查后才报告添加并认证成功。DHCP 超时、账号错误或认证受拒时返回非零退出码，明确说明新接口已保留但当前离线；保留受保护凭据，供用户修正后手动 refresh 使用。不存在后台认证重试。

成功后 MAC 持久化固定。认证失败也不生成第二个身份；未来 refresh 对同一 MAC 重试，remove 删除对应接口与凭据但保留 MAC 历史。edit 改动 MAC 后，旧凭据绑定失效，需要用户重新确认，不能默默沿用。

是否允许一个新随机 MAC 取得 DHCP 并通过账号认证，仍取决于实际校园网接入策略。此前现场验证的是已有主 WAN MAC 的登录协议，不是任意新 MAC 的接入许可。

## ePortal 请求处理

- 健康检查、门户发现、pageInfo/getServices、登录和登录后验证都绑定目标 WAN 的当前 IP，防止备用出口掩盖目标线路故障。
- 每轮从新跳转 URL 取 queryString，不在配置中固化完整认证 URL。按现场门户的实际双层 URL 编码规则提交登录表单。
- portal origin/path 来自无秘密的受信配置，并校验发现到的 URL；不跟随任意跳转把密码发给另一个主机。
- 不执行注销、踢设备、修改 MAC 或注册无感知认证等额外账户操作。
- 不输出原始请求、服务器完整响应、userIndex、认证 URL 查询参数、用户名或密码。
- 可以使用已有 curl/jsonfilter 实现，无需为了认证把整个桌面 Go 应用部署到路由器。密码编码必须覆盖空格、中文和 `&`、`%`、引号等特殊字符。
- 不把密码作为 curl 参数、环境变量或 jsonfilter 的 `-s` 内容传递。正文经标准输入送入 curl；JSON 文件按数据读取，不使用 `source`、`.` 或 `eval`。

## 凭据存储

推荐采用路由器本地、按 WAN 独立配置的文件，例如：

```text
/etc/hitwh-mwan/auth.d/          root:root 0700
  wan.json                     root:root 0600
  wan2.json                    root:root 0600
```

默认没有任何凭据文件。只为需要手动认证的线路创建配置；不默认把一份账号共享给所有 WAN。文件可记录对应 WAN/MAC 以避免把旧配置用于不符的终端身份；修改 MAC 后应提示用户重新确认该认证配置。

提供以下交互命令，命令行中只出现 WAN 名称：

```sh
# SSH 交互配置；保存不会提交登录
hitwh-mwan auth set wan
hitwh-mwan auth status
hitwh-mwan auth remove wan
```

`auth set` 在已验证的 SSH 连接中交互读取用户名和密码，不回显密码，不通过命令行参数接收密码。dashboard 也可通过凭据弹窗录入；配置成功本身不触发登录。

写入要求：

- 仅 root 可配置和读取；设置 `umask 077`，检查目录/文件的属主和权限，拒绝符号链接及非普通文件。
- 在同一私有目录创建临时文件并原子替换；正常结束和中断均恢复终端回显、清理临时文件。
- 不往普通 UCI `/etc/config/hitwh_mwan` 中写密码，避免随 `uci show`、现有配置备份或公开诊断信息带出。
- “线路负载”按 WAN 提供“添加凭据/查看凭据”。只有显式弹窗操作才通过 LuCI 的受保护 RPC（电脑调试模式为本机 POST + SSH）读取、保存或删除凭据；已有账号密码可编辑，密码默认遮盖，显式勾选才显示。
- 路由器模式使用 LuCI 会话/ACL 和同源桥接；电脑调试请求要求本机 Host、同源 Origin、专用请求头和 `no-store`。服务端不缓存凭据，关闭弹窗清空输入，迟到响应不能重新填入已关闭的弹窗。浏览器 localStorage/sessionStorage、URL、采样 JSON 和前端源码都不存秘密。
- `auth status` 只显示某条线路是否有配置及权限是否合格，不显示用户名或密码。
- 删除配置后，下次刷新只进行健康检查和必要的 DHCP 恢复，不提交登录。

此方案使用访问权限保护明文文件。它能限制普通用户读取，但无法保护已被 root 控制的路由器；不能将它描述为“加密存储”。对需要 unattended 读取的秘密，把解密密钥和密文放在同一台路由器上，也不能解决这一问题。

如果用户要求静态加密，则采用独立口令加密，并在每次手动刷新时由用户解锁。解锁密钥仅在本次操作的内存中存在。这会改变 CLI 和 dashboard 的操作流程，需要作为独立可选方案设计，不能伪装成无交互的安全保险箱。

当前现场只验证了 HTTP 门户登录，HTTPS 443 探测超时；文件权限不提供传输加密。凭据录入使用 SSH，但路由器至门户仍服从校园网实际提供的登录协议。不能通过关闭 TLS 证书校验来宣称已获得安全 HTTPS。

## 仓库、升级与备份

- 真实凭据只在路由器的私有目录创建，不在任何开发工作区生成。
- 仓库只包含实现代码与空值示例；测试使用虚构账号，不使用用户在会话中提供的账号或密码。
- `.gitignore` 排除认证目录、私有凭据文件和原工具的真实 config.toml；只允许明确命名的空值示例。
- 提交前与 CI 拒绝实际凭据文件并执行秘密扫描。不能为扫描而把用户的真实秘密硬编码进扫描器。
- 安装/更新脚本不复制、打印或上传凭据；诊断包、状态接口和项目配置备份默认不收集认证目录。
- 默认不主动把凭据目录加入 sysupgrade 保留列表。若用户选择保留，明确告知系统备份会包含秘密，并保护备份；完整磁盘备份也可能包含该目录。
- 卸载时通过显式选项处理凭据保留或删除，不把凭据复制到普通配置备份目录。

## dashboard 与超时

保留人工触发边界。页面轮询只读状态，GUI 的独立刷新和全体刷新通过 rpcd 任务调用同一管理入口；电脑调试模式才需要 SSH。

新增固定格式的逐线路结果，例如 `AUTH_RESULT wan success`、`AUTH_RESULT wan2 missing_credentials`。结果只含受管接口名称与固定状态码，dashboard 将其转换为“未配置凭据”“需要验证码”“认证失败”等提示，不展示门户原始消息。

认证 HTTP 请求连接超时 3 秒、总超时 5 秒、响应上限 64 KiB；每条线路最多 5 次请求和一次登录。认证最多并发 3 路。路由器整轮刷新设置 270 秒预算，dashboard 超时 300 秒。正常退出或中断会终止认证子进程并清理私有临时文件；预算到期不会继续排队认证。

## 验收要求

1. 模拟主 WAN 认证失效，后台跨越多个检查周期仍不提交登录，只退出分流池并切到副 WAN。
2. 手动 CLI 刷新提交一次目标 WAN 登录，成功后通过 204 检查才重新上线。
3. dashboard 点击得到同一行为；页面打开、自动轮询和浏览器 F5 不提交登录。
4. 所有在线线路不参与认证；保留编号和非受管接口不参与恢复。
5. 没有凭据、没有 DHCP、凭据权限错误、密码错误、验证码/加密要求、门户不匹配或网络超时均产生有限、可解释的失败。
6. CLI 与 dashboard 同时刷新不会双重登录；请求失败不启动背景重试。
7. 使用带特殊字符的虚构凭据验证表单编码；模拟门户在失败消息里回显密码，确保 stdout、stderr、日志、状态和 dashboard 响应仍没有该值。
8. 检查认证子进程的参数和环境不包含秘密；仓库、构建产物、示例和提交内容没有真实凭据。
9. add random 生成本地管理单播地址，遇到当前、保留、非受管、运行时或历史 MAC 冲突时重新生成；随机源失败或候选重试耗尽时不创建线路。
10. 添加时取消凭据输入、容量已满或并发添加均不会覆盖已有线路或凭据；创建后认证失败显示保留的接口与固定 MAC，后续仅手动 refresh 才重试。
11. add random 只认证本次新建接口。添加后的掉线、系统重启、页面采样和普通 add <MAC> 不提交登录；remove 后随机生成继续避开历史地址。

已有单次主 WAN 登录实测说明协议可行。自动化测试覆盖触发边界、请求源地址、特殊字符编码、权限与秘密不泄露、随机地址冲突、创建回滚和失败后保留；浏览器验证覆盖弹窗保存/查看、密码遮盖、关闭清理和手动刷新。随机 MAC 的真实 DHCP/校园认证验收需用户现场执行 `add random`，隔离测试不代替接入策略验证。
