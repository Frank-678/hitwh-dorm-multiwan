# 连接轮询与现场验证

默认的 `balance_mode=round_robin` 使用 nftables `numgen inc mod N`，按顺序把新连接分给在线出口。TCP、UDP 各有自己的生成器，DNS 等 UDP 短连接不会占用 TCP 的轮询顺序。既有连接保持原来的连接跟踪标记和 NAT 出口。

算法只改变尚未标记的新连接。普通健康检查保留规则和生成器状态；只有算法、在线出口集合变化，或防火墙规则发生漂移时才事务更新。单出口直接使用唯一标记。未设置该 UCI 选项也默认采用轮询；非法值会在网络修改前返回错误。

## 2026-10-04 六出口对照

环境：RAX3000M、OpenWrt/Kwrt 24.10 系固件、六个已认证 macvlan/DHCP 出口、Windows 有线客户端。单出口在此前固定出口下载中约 6 MB/s。所有速度均为十进制 MB/s。

### 固定 CDN、固定文件、固定并发

暂时退出 Steam 排除带宽争用。客户端同时发起 12 条 HTTP/1.1 HTTPS 连接，固定到同一 CDN IPv4 和同一个游戏资源文件；每条下载相同的 128 MiB 字节范围，数据丢弃到空设备，每轮总量为 1,536 MiB。连接未绑定具体 WAN，由路由器实际分配。健康监控保持运行。

先后测试随机、轮询、随机、轮询，每轮都重建测试连接。连接跟踪用于确认每条连接的出口，curl 用于确认 HTTP 206、完整字节数和退出码。表中连接数按六个出口依次列出。

| 模式 | 完成时间 | 整个任务平均吞吐 | 出口连接数 | 连接公平指数 |
|---|---:|---:|---|---:|
| 随机，第 1 轮 | 89.34 s | 18.03 MB/s | 1 / 4 / 3 / 1 / 2 / 1 | 0.750 |
| 轮询，第 1 轮 | 45.00 s | 35.79 MB/s | 2 / 2 / 2 / 2 / 2 / 2 | 1.000 |
| 随机，第 2 轮 | 111.63 s | 14.43 MB/s | 1 / 2 / 1 / 2 / 5 / 1 | 0.667 |
| 轮询，第 2 轮 | 45.25 s | 35.59 MB/s | 2 / 2 / 2 / 2 / 2 / 2 | 1.000 |

48 条请求全部完整完成，HTTP 206、curl 退出码均为 0。平均吞吐按总有效下载字节数除以整个任务耗时计算，耗时包含启动和采样结束开销；不是瞬时峰值。公平指数使用 Jain 公式 `(sum(x))² / (N * sum(x²))`，这里的 `x` 为每个出口承载的等量连接数，1 表示完全均分。

这个场景下，随机把较多工作分给少数出口，其余出口提前空闲，拖长整个任务；独立轮询显著减少了这一现象。只有两组对照，不代表所有随机分配都达到相同速度，也不是统计意义的长期带宽保证。

### Steam 真实下载

Steam 下载同一游戏，下载区域与代理策略在这两个采样窗口保持一致。每次通过本机代理 API 仅关闭 Steam CDN 下载连接，使其重新分配，等待 30 秒，再连续采样约 90 秒。未改变代理节点或区域。

| 模式 | Steam 连接接收平均 | WAN 总接收平均 | 出口流量公平指数 |
|---|---:|---:|---:|
| 原随机 | 19.94 MB/s | 21.10 MB/s | 0.826 |
| 独立 TCP/UDP 轮询 | 21.65 MB/s | 22.64 MB/s | 0.854 |

Steam 按相关 CDN 连接接收字节差计算，WAN 统计包含其他流量；结束采样前已消失连接的最后一段流量可能漏计。WAN 父接口已经包含 macvlan，副出口只用于拆分，不能再与父接口相加。主出口由父接口减去各副出口估算。

Steam 本轮约提升 8.6%，幅度有限，且只有一次前后对照，不能把受控测试的近两倍吞吐推广为 Steam 必然提速两倍。不同 CDN 的连接速度、HTTP/2 复用以及代理中的连接合并仍会影响负载。部分 Steam CDN 走直连，另一部分沿现有代理策略转发；本次没有修改这些策略。

### 刷新稳定性与检查

部署与 Steam 对照期间，`ip monitor route rule` 连续观察约 145 秒，没有路由或策略规则事件。监控一直运行，六路在线；算法不迁移既有连接、不清空策略路由表。

验证通过：Shell 语法与项目检查、10 项真实更新脚本隔离回归测试（Windows/Git Bash 与 Linux/WSL）、8 项仪表盘测试。回归覆盖重复刷新、地址变化、失效出口兜底、防火墙漂移修复、nftables 提交失败，以及模式切换、TCP/UDP 独立轮询、非法模式拒绝。

## 配置与恢复

```sh
# 默认轮询
uci set hitwh_mwan.main.balance_mode='round_robin'
uci commit hitwh_mwan
hitwh-mwan list

# 恢复原随机分配
uci set hitwh_mwan.main.balance_mode='random'
uci commit hitwh_mwan
hitwh-mwan list
```

切换不重新分配已经建立的连接，应用之后新建的连接才使用新算法。测试时需要主动重建下载连接；不要通过清空连接跟踪或删除策略路由来迁移它们。

轮询的目标是减少新连接随机扎堆。它不根据实时流量调整权重，也不保证所有连接流量相同。已有重下载连接长期占满某个出口时，其他新连接仍可能被分到那里。对带宽或质量差异很大的出口，后续可单独评估带负载反馈的权重算法，不能仅凭轮询结果假定等权适用于所有环境。

生成器语义见 [nftables 官方手册](https://netfilter.org/projects/nftables/manpage.html)。
